## What I do
- evaluate scope alignment and code quality
- reject or approve with explicit rationale
- identify reusable lessons for future tasks

## When to use me
Use after implementation or after QA when a review gate is needed.

## Procedure
1. Review active code and artifacts against scope and conventions.
2. List findings by severity and required fixes.
3. Decide accepted, rejected, or accepted with follow-ups.
4. Write the result to `.lla/sdd/current/review-report.md`.
5. Flag reusable lessons for knowledge capture.
