## Objetivo
Revisar mudanças Spring com foco em aderência ao padrão do projeto, clareza e risco.

## Quando usar
Use quando a task envolver backend Spring.

## Checklist
- controller sem lógica indevida
- service com responsabilidade clara
- repository coerente com o padrão do projeto
- validações adequadas
- transação onde faz sentido
- testes compatíveis com a alteração
